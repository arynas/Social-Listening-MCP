# Changelog

## 0.0.1 (unreleased)
Foundation for data-agnostic social-listening tools (F0–F5).
- Post schema with validation (`slmcp/schema.py`).
- Adapter interface with one shared query rule set and a reusable contract test suite (`slmcp/adapters/base.py`).
- Adapters: in-memory, CSV/JSONL files, RSS/Atom news feeds.
- Synthetic data generator with a fixed seed (`scripts/make_synthetic.py`).
- Snapshot builders for public GDELT news metadata: DOC API and raw translingual GKG files.
- Sentiment labelling with an OpenAI-style endpoint and a blind hand-check tool.
- YAML config (`config.example.yaml`): switch the data source without code changes; keys only from environment variables.
- Datasheet: sentiment labels for the 1–14 Oct 2026 snapshot (43,422 headlines; model-assigned; blind hand check of 100 rows: 63% agreement, kappa 0.44).
- Data snapshot published as GitHub Release `data-2026-10-v1` (labelled headlines, manifest, datasheet, checksums); README shows how to download and load it.
- Recap logic (`slmcp/recap.py`): totals, sentiment with percentages that add up to 100, trend per WIB day or week, top lists, samples, relative dates, data warnings, a ~2,000-token size limit; `news_recap` / `social_recap` as plain functions. Config: `today` and `data_source.sentiment_labels`; `config.snapshot.example.yaml`.
- MCP server (`slmcp/server.py`, `slmcp-server` command) with `news_recap` and `social_recap`, built on the official MCP Python SDK (`mcp>=2.3,<3`); stdio and Streamable HTTP; keyword and date checks with clear errors; one JSON log line per call; proof run calls the tools through MCP.
- Client trial with OpenCode and Qwen3.6-27B on 5 questions (`docs/client-trial.md`); README Quickstart from zero.
- CI (lint, tests on Python 3.11 and 3.12, package build, proof run) and security checks (CodeQL, gitleaks, pip-audit).
- Failure table and V&V checklist for the public version (`docs/failure-vv.md`), numbered like the regression tests.
- `detect_spikes` tool (S1-1): spikes in daily or hourly counts against a trailing robust baseline (median + MAD), separate negative-news spikes, settings in `spikes:` in the config (`docs/spikes.md`). Benchmark runner `--tools` (default: the two v1.1 tools, so v1.1 results stay comparable).
- `detect_spikes`: when the baseline median is 0 a spike needs at least `min_count_zero_median` posts (default 10); back-to-back spike days/hours are merged into one event with start, peak and end.
- `compare_keywords` tool (S1-2): 2 or 3 keywords side by side for one period: totals, sentiment, daily (or hourly) trend, differences and ratios per pair, overlap; same keyword matcher and strict data range as `news_recap` (`docs/compare.md`).
- `entity_trend` tool (S1-3): daily (or hourly) trend of one keyword with sentiment, peak, change against the previous period of the same length (null when that period is not inside the data), and the top 5 stories (`top_posts`: similar headlines grouped, ranked by distinct sources; by engagement for social data). Config `trend: story_similarity` (default 0.5; `docs/trend.md`).
- `docs/compare.md`: substring matching kept for now (decision 20 Nov 2026); known limits noted.
- Benchmark v2 questions and scoring (S1-5 part 1): `benchmark/questions-v2.jsonl` (350 items: the 226 v1.1 items re-scored on the 44-day snapshot + 124 new items for `detect_spikes`, `compare_keywords`, `entity_trend` and trap questions), gold computed by `slmcp.bench.build_v2`, tool-selection scoring (right / ok / wrong / none / extra, args) by condition (2 vs 5 tools). Needs release `data-2026-10-v2`; v1.1 is unchanged.
- Config: a `csv`/`jsonl` source can list several files (e.g. one per month); `config.snapshot-s1.example.yaml` for the 44-day snapshot.
- Benchmark v2: 3 fixed-range spike questions without a spike (n004–n006) replaced by ranges around hand-checked events with a spike (Ari's choice, 20 Nov 2026); 4 spike items now have "no spike" as the right answer (one of them the nonsense keyword).
- Tool descriptions (after the S1-5 Qwen run): `detect_spikes` is for unusual jumps, not the busiest day (use `news_recap`); `entity_trend` is for the peak day, "naik atau turun?" and "berita utama"; `news_recap` keywords leave out words like naik/kenaikan. Tool list about 1,650 tokens (test limit 1,700).
- Benchmark scorer: more "no spike" wordings count as correct (e.g. "no statistical spikes detected", "tidak terdeteksi adanya lonjakan").
- The raw GDELT snapshot builder retries timed-out downloads up to twice. Sentiment labelling reads the resume checkpoint once per run.
- Prepare local news report facts and an outline from the configured adapter with `python -m slmcp.report` (S2-1).
- Optional HTTP report tools preview an outline, queue a checked render after browser approval, and return PowerPoint and PDF download links (S2-2).
- Local Analyst Agent pilot connects the two MCP news tools with evidence-linked analysis, outline approval, S2 report verification, and per-run trace files (S3-1).
- The draft reviewer reruns report checks, evaluates whether conclusions follow from their evidence, and routes a bounded revision loop (S3-2).
- Open WebUI links to the checked S3 report for version-bound human approval, change requests, and rejection. Only approval of the current version records a simulated delivery (S3-3).
- The S3 analyst can retrieve dated context via separate MCP web and knowledge-base tools, cite passages, and disclose disagreements and service outages in the reviewed brief (S3-4).
- S3 can bind a report run to a configured dataset ID. Simulated delivery checks the target and approved version before recording a local receipt (S3-6).
- S3 traces retain replay inputs and artifact hashes. Offline replay reconstructs data and review decisions and can rerun the local checker on saved report files (S3-7).
- S3 checks action kind, target and scope before execution, escalates pending checks or approval and external delivery, and records scoped policy decisions in the review audit (S3-8).
- S3-5 hard cases: six paired S2/S3 cases with gold and rubric fixed before the run (`benchmark/s3-hard-cases.json`), a deterministic pre-scorer (`slmcp/hard_cases.py`) and a runner (`scripts/eval_hard_cases.py`).
- The S3 reviewer retries once when the model returns invalid JSON and fails cleanly after a second invalid reply (found with Torcons-Pax in S3-5).
- Streamlit demo page (`apps/streamlit/`, optional extra `streamlit`): one chat with in-chat tool switches and shortcuts for the data tools, the checked report flow and the read-only final review status. Every tool call is shown with arguments and raw result; numbers come only from the MCP tools. Tool loop tested with a fake model and fake tools.
